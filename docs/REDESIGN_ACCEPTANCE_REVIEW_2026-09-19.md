# 知识体验重构：代码审查与效果验收

审查日期：2026-09-19。审查版本：`389137db9aa01cc91acdb9adf53948eb1137db2c`，分支 `codex/knowledge-experience-redesign`。

**结论：不通过整体交付验收。** 新应用壳、路由、主题、部分异步任务和图形技术已接入，但主线图存在实际空白故障，关系语义、理解练习持久化、星图定位/邻域及静态模式均有缺陷。当前状态应描述为“重构中的可运行基础版本”，不能描述为“方案已经实现，只差录屏”。

验收依据为 `FRONTEND_VISUAL_MOTION_SPEC.md` 和 `KNOWLEDGE_EXPERIENCE_REDESIGN.md` 中的功能、语义、分镜及完成定义。本文保留原方案标准，不因为修复成本或实现阶段而降低标准。

## 1. 方法、证据与边界

- 阅读前后端实际调用链，核对 API 字段、数据保存、组件及渲染生命周期。
- 实际浏览默认生产资源，检查工作台、材料页、知识脉络、星图及问答；读取 DOM、截图和计算样式。截图已在审查会话中展示，未把单帧截图当作动画验收通过依据。
- 本轮续审启动 `127.0.0.1:8001` 隔离服务：通过 SQLite backup 从原库只读复制快照，后续访问使用副本。该进程禁用 DeepSeek/Tavily 密钥；问答观察属于本地检索降级，不代表在线模型质量评测。
- 用合成材料和 mock 调用复现关系转换、练习写入、否定回答评分、生成参数传递及真实生成路由的取消状态。脚本位于 `scripts/audit_redesign_acceptance.py`，不会调用模型或写入业务数据库。
- 前端构建输出到被忽略的 `frontend/.tmp/audit-build`，没有覆盖生产静态资源。现有任务/复习测试使用测试临时数据库。
- 本文区分“浏览器复现”“隔离复现”“代码确认”和“未测”。未进行全量测试、在线模型的 12 份固定材料评测、手机实机测试、四条完整分镜录屏、2,000/10,000 节点性能测试或 GPU 泄漏测量。

P1 表示核心功能/知识正确性受到影响，应在交付前优先修复；P2 表示明确的功能或稳定性缺陷，仍需在对应验收项关闭前修复。

## 2. 已确认的问题

### F01 · P1 · 单篇脉络的边契约不匹配，实际画布空白

**位置：** `frontend/src/components/KnowledgeScene.tsx:20,30–37`；`frontend/src/types.ts:31–32`；`app/web/routers/graphs.py:336`；`app/services/knowledge_contract.py:69–96`。

**复现：** 打开已有脉络 `60754768b2b4`。右侧有节点解释，标题显示 19 个知识点，但 React Flow 节点、边元素均为 0，画布没有可读主线。接口包含 19 个节点、77 条 `links`、111 条 `structure.edges`；77 条 `links` 均至少有一个端点不在当前图节点集合内。将当前适配逻辑的输入交给项目安装的 ELK，得到：

```text
org.eclipse.elk.graph.json.JsonImportException:
Referenced shape does not exist: 6738ce96bec9
```

**原因：** 页面优先选取跨图 `detail.links`，却只向 ELK 提供单篇节点；没有校验端点是否存在，布局错误又被 `.catch(() => undefined)` 吞掉。即使 `links=[]`，空数组为真，也不会使用 `structure.edges`。规范边端点为 `from/to`，前端类型及适配器却认 `source/target`，直接切换数组仍不能解决问题。

**修复要求：** 统一内部边契约；分别处理单篇结构边与跨图引用；布局前校验引用；无边时也应显示节点；错误提供明确提示和可读降级。复测含“只有层级、只有关联、存在跨图边、无效端点、零边”五类材料。

### F02 · P1 · 关系类型与证据状态在转换/保存时失真

**位置：** `app/services/knowledge_contract.py:63–96`；`app/services/graph_generation.py:362–373`。

**隔离复现：** 输入 `a causes b` 的节点数据，经规范视图转换后变成 `a related b`；`b.parent_id=a` 生成 `a depends_on b`，并标记为 `confirmed`，即使该层级边没有证据。脚本同时保留了原因果证据字符串，说明有证据文本也不能保住关系类型。

**原因：** 持久化节点时没有保存独立关系类型/状态/证据对象；`related_nodes` 被统一转成无向去重的 `related`。父子层级统一当成依赖，偏离方案规定的“上层 contains 下层”和“A 依赖 B”的方向语义。普通说明 `note` 被充作边证据，状态统一确认为 `confirmed`。

**修复要求：** 定义并持久化独立的带方向关系对象；为旧关系保留“不明/待确认”状态；区分原文摘录、推断解释与节点说明。用因果、包含、依赖、对比、例子和双向关系验证生成→保存→读取→渲染的往返一致性。不能只替换前端关系名称。

### F03 · P1 · 默认理解练习没有写入复习历史，却触发持久化事件

**位置：** `app/services/review.py:77–92,215–235`；`frontend/src/App.tsx:129–132`。

**隔离复现：** 真实到期条目带 `review_id` 对应的 `id`，转成 Feynman 题后丢失该关联；提交文本和 `rating=2`，`submit_review` 调用次数为 **0**。前端默认固定请求 `feynman`，收到普通反馈后立即发出 `review.persisted`。

**影响：** 用户已经做题，但 FSRS 排程和复习历史没有随该次作答更新，“掌握度回到知识空间”的承诺不成立。前端还固定代填评分 2，没有方案要求的用户自评步骤；最后一道题没有完成报告或结束入口。

**修复要求：** 将语义反馈与正式自评分开；给所有练习目标建立可追踪的复习记录；正式提交返回确实更新的 concept/review ID 和版本，成功后才能触发动效。重复提交需幂等；失败不得显示成功信号或让下一题绕过本题状态。

### F04 · P1 · 词面重合被当成理解评分，否定答案得到 96% 正向反馈

**位置：** `app/services/review.py:306–325`。

**隔离复现：**

| 项目 | 输入/结果 |
| --- | --- |
| 参考答案 | 过拟合会降低模型的泛化能力。 |
| 学生回答 | 过拟合不会降低模型的泛化能力。 |
| 实际反馈 | 回答已覆盖主要概念（约 96%），可以再补充一个条件或例子。 |

算法只统计字词与双字片段交集，无法判断否定、因果方向或条件。主方案明确要求具体纠错和依据，且禁止未经校准的细粒度百分比。

**修复要求：** 以命题、条件、关系和证据判定回答；无可靠语义判定能力时明确说明只发现了哪些关键词，不能据此宣称理解正确。固定评测必须包含否定、因果颠倒、漏条件、关键词堆砌与正确改写。

### F05 · P1 · 跨页概念定位没有接通

**位置：** `frontend/src/components/KnowledgeScene.tsx:20`；`frontend/src/components/GalaxyScene.tsx:9–20`。

**浏览器复现：** 点击“在星图中定位”后 URL 为 `/galaxy?concept=9144e171b6a2`，但星图仍展示总览，详情仍提示“点击星体，查看概念来源、关系和学习信号”，没有选中或定位该概念。副本服务上直接打开同一深链结果一致。

**原因：** 出发页传递概念参数，星图完全不读取参数；选择与镜头只存组件局部状态。问答也没有“答案概念→星图”的交互入口。

**修复要求：** 采用稳定 concept ID 贯通 URL、选择、镜头、详情和返回状态；处理概念尚未加载、不存在、历史别名等情况。完成分镜 B 的真实端到端操作，而非仅添加跳转链接。

### F06 · P1 · 搜索提前删除邻居，“展开邻域”无法找回真实关系

**位置：** `frontend/src/components/GalaxyScene.tsx:19–21,46–48,66–70`。

**浏览器复现：** 星图有 523 个概念。搜索 `LangSmith` 显示 3 个匹配，Enter 选中 LangSmith，再点“展开邻域”，画面仍只有搜索匹配概念，没有展开其非匹配邻居；长标签在右侧被裁切。

**原因：** 搜索先从传给渲染器的数据中删去不匹配概念；布局和端点映射只基于剩余节点。绘边时缺少端点的关系直接被跳过。“展开邻域”仅再次设置相同 `focusId`，没有取回邻域节点。

**修复要求：** 搜索作为焦点/高亮或候选列表操作，底层保留全量身份索引；邻域由真实边展开，并保留方向、类型、状态和证据。以标签不含搜索词的一跳邻居作为必测样本。

### F07 · P1 · 静态模式并未全局生效，刷新后偏好丢失

**位置：** `frontend/src/styles.css:6,11,55`；`frontend/src/motion.ts:16–26`；`frontend/src/components/GalaxyScene.tsx:90–92`；`frontend/src/App.tsx:50`。

**浏览器复现：** 切换“静态”，进入材料页读取实际样式，`documentElement.dataset.motion=static`，但 `.mini-network path` 仍为 `animationName=dash`、`animationDuration=15s`、`animationPlayState=running`。刷新页面后下拉框恢复“完整”。

**代码确认：** 静态 CSS 只覆盖部分选择器，遗漏图谱边与材料 SVG；Pixi ticker 未读取动效偏好；系统减少动画值只在构造时读一次，没有变化监听。选中概念的圆环以全局坐标画在 Graphics 中再缩放整个对象，会连同圆心一起相对原点移动，不能稳定贴合焦点。

**修复要求：** 用可订阅的单一偏好状态驱动 CSS、Motion、Pixi 和镜头；保存设置；响应系统偏好变更；静态/后台停止相关循环。复测中途切档、刷新、系统偏好变化、焦点固定及页面隐藏恢复。

### F08 · P1 · 学习目标与深度在主要文本生成调用链丢失

**位置：** `app/graph/builder.py:26–41`；`app/graph/agent.py:185–211`；`app/tools/react_tools.py:19–29`；`app/services/graph_generation.py:408–427`。

**隔离复现：** 向 `tools_node` 提供 `learning_goal=比较因果机制`、`generation_depth=deep` 并调用生成工具，最终 `generate_and_save_graph` 收到的参数只有正文及 `output_format=both`。不是前端未提交：API 已把字段放入状态，但工具 schema/调用链没有继续传递。

**关联问题：** 可接收这些参数的 `generate_graph_fields` 又把“学习目标”和“展开深度”作为 Markdown 章节拼进材料正文，再用于生成/长文分析。隔离探针已经确认输入正文被改写；是否具体生成伪知识节点取决于生成分支，本轮未把该后果当作已完成在线复现。

**修复要求：** 将正文、来源元数据、用户生成约束作为独立参数贯穿所有路径。文本、文件解析后正文、URL 解析后正文和长文应使用同一契约。通过 spy/契约测试验证参数到达生成器，再用固定材料检验不同目标的实际内容差异。

### F09 · P2 · 生成取消/超时异常被包装成普通失败

**位置：** `app/web/routers/graphs.py:176–192`；`app/services/jobs.py:67–85,118–130`。

**隔离复现：** 运行真实 `generate_graph_async` 路由，只用可暂停的假 graph 替代模型执行；收到取消请求后放行一个 stream 事件，最终任务返回 `status=error`、`stage=失败`、`error=脉络生成失败: `、`cancel_requested=true`。通用 jobs 单测可以通过，实际生成路由仍然错误。

**原因：** 路由的 `except Exception` 吞掉 `JobCancelled/JobTimeout` 的专有类型。取消检查在 stream 产出之后，不能据此保证此前的工具保存没有发生；超时是合作检查，不是中断阻塞调用的硬截止。

**修复要求：** 保留专有异常，明确可取消边界，保存前检查任务状态；明确“请求取消”与“确认取消”的区别。验证取消前后是否存在保存、副作用是否重复、超时后的结果如何处理。不能只测试通用 jobs runner。

### F10 · P2 · 问答结果与来源契约断裂

**位置：** `app/web/routers/knowledge.py:55–66`；`app/services/knowledge.py:49–52,102–108`；`frontend/src/App.tsx:124`；`frontend/src/types.ts:58–64`。

**浏览器复现：** 输入 `LangSmith`，本地检索返回 23 个来源。回答区的问题标题为空；前 4 张实际为库内脉络的来源卡片被标成“网页来源”，且全部 disabled；记忆来源也退化为通用“知识来源”禁用卡片。

**原因：** 异步接口直接返回 service 结果，没有同步接口中的 `question`。脉络来源用 `id` 保存图 ID，前端仅识别 `graph_id`；前端还忽略 `source.type` 和 `url`，用“没有 graph_id”推断网页来源。节点来源虽然可打开图，也没有定位具体节点/原文段落。

**修复要求：** 采用可判别的来源类型契约，分别提供图、节点、原文段、记忆、网页的有效动作；异步和同步回答契约一致。复测每类来源的打开、定位、返回与不可用状态。

### F11 · P2 · 每次选择重建布局/渲染器，资源生命周期不完整

**位置：** `frontend/src/components/KnowledgeScene.tsx:27–38`；`frontend/src/components/GalaxyScene.tsx:18–20,36–97`。

**代码确认：** 单篇图 effect 依赖 `selected` 及每次渲染新建的 `onSelect`；每轮又 `new ELK({workerUrl})`，清理只修改布尔值，没有保存实例并终止 worker。星图 `compressGalaxy` 与 `selectConcept` 每次 render 都产生新引用，同样触发整套 Application 销毁/重建。

**影响：** 高频选择/筛选会触发无必要的重新布局与纹理/场景创建，破坏方案要求的空间连续性。遗留 worker 的数量和 GPU 内存增长尚未测量，不在本文中虚报具体泄漏数值。

**修复要求：** 区分结构变化、选择变化、镜头变化；渲染器和 worker 具有明确生命周期，选择仅更新样式和局部对象。对连续打开/关闭 10 次、连续选择、缩放搜索和快速切页测量资源回收。

### F12 · P2 · 工作台指标不是其声称的真实数据，生成后列表不会自动更新

**位置：** `frontend/src/App.tsx:24–27,72`。

**代码确认：** “本周连接活跃度”宽度为 `Math.min(100, graphs.length * 12)`，没有时间窗口、连接变动或行为数据；9 份材料即可显示满格，与本周活跃程度无关。图列表仅挂载时获取一次，生成完成后没有失效/刷新机制。

**修复要求：** 为指标给出真实口径；没有数据则明确显示暂无统计。生成/删除/重命名后同步更新列表与统计，用同一会话内操作验证首页立即反映真实状态。

### 3.2 四条动效分镜
